Getting Started

  • Drop or click Source JSON to load the reference file.
  • Drop or click Target JSON to load the file you are editing.
  • The editor opens automatically once both files are loaded.
  • Click Reset to start a new session. You will be prompted if there are unsaved changes.

Editor

  • Source values are on the left (read-only by default). Edit values in the right column.
  • 🔒 / 🔓 unlocks a source field if you need to correct the reference text.
  • 📋 copies the source value into the target field. Appears when the two values differ.
  • ↺ undoes the last copy and restores the previous target value.
  • 👁️ dismisses an exact-match or length warning for that item without changing the value.
  • A character and word count is shown below each field as you type.
  • A length warning is shown when the target exceeds 1.5× the source character count. Use 👁️ to dismiss if the longer value is intentional.
  • Placeholders like {{name}}, %s, {key}, and %1$s are highlighted in the source. Missing or extra ones in the target are flagged so interpolation does not break at runtime.
  • ICU message format ({count, plural, one {# item} other {# items}}) is detected automatically. When either ICU setting is active, the source breaks into individual cases. Enable ICU format validation to flag missing cases and variable mismatches; enable ICU sub-field editing to edit each case in its own field and add extra cases the source does not have (e.g. few, many). The two settings are independent.
  • Special characters (< > " & `) trigger a warning because they can break HTML rendering or JSON parsing depending on how the application consumes the strings.
  • A blue border marks fields whose current value differs from what was loaded at the start of the session, making it easy to see what you have changed.
  • Right-to-left text direction (Arabic, Hebrew, Persian, etc.) is detected automatically per field based on Unicode character ranges and applied without any manual setup.
  • Nested keys are shown as dot-separated paths. Array items use [0], [1] index notation. The original structure and key order are preserved when you save.

Item Status Colours

  • Missing Key exists in source but is absent from the target file entirely.
  • Empty Key exists in target but its value is an empty string.
  • Extra Key is present in target but has no corresponding source key. May be obsolete.
  • Type mismatch Same key but the value type differs (e.g. string vs. array).
  • Exact match Target value is identical to the source. The value may not have been updated yet.

Filter Bar

  • Type to filter by key path, source text, or target text. Type a segment number (e.g. 25 or #25) to jump directly to that segment.
  • Use a regex by wrapping it in slashes: /pattern/flags (e.g. /^auth\./i to show only auth-related keys).
  • Missing and Empty are the most useful status filters when working through outstanding segments.
  • Changed shows only segments whose target differs from the originally loaded value, useful for reviewing edits before saving.
  • Warnings shows segments that have any active warning (length, exact match, special characters, placeholder, or ICU validation). Respects warning toggles in Settings. If a warning type is disabled, those segments will not appear here.

Progress Bar

Shows how many segments are done out of total. A segment counts as done when the target is non-empty, has no empty ICU cases, and either differs from the source or its exact-match warning has been dismissed.

Floating Buttons (bottom right)

  • 💾 green saves the source JSON as a download.
  • 💾 blue saves the target JSON as a download. Will not save if any keys are still missing or empty.
  • ↑ / ↓ scroll to top or bottom of the list.
  • 📊 exports a CSV with key, source, target, and max-characters columns. The max-characters value is ceil(source length × threshold) using the same threshold set in settings (default 1.5×), so you can pass character limits directly to designers or developers.
  • 🌓 toggles dark and light theme. Your preference is saved across sessions.

Missing Translations Toolbar

Appears when there are empty or missing keys. Export just those segments as a JSON snippet, fill them in externally, then import the completed file back. Useful for handing off partial work without sharing the full file.

Session History

Logs every load, edit, save, import, and export during the session. Collapsed by default.

Search and Replace

Click Replace in the filter bar to open the replace row. Enter a find term and a replacement, then click Replace visible to apply to all currently visible target fields that match. Supports the same /regex/flags syntax as the filter. The replace is scoped to visible rows, so filter first to narrow the target set. Ctrl+Z undoes the last programmatic change (copy or replace) on the focused field.

Keyboard Shortcuts

  • Ctrl+S saves the target file.
  • Ctrl+Enter moves focus to the next target field.
  • Tab / Shift+Tab moves forward and backward through visible target fields.
  • F8 jumps to the next empty target field, based on the active filter.
  • Ctrl+Z inside a target field undoes the last copy or replace operation on that field.
  • Escape closes the settings or help panel, or the replace bar.

Settings

Click ⚙️ to open settings. All settings are saved to localStorage and persist across sessions.

  • Length warnings flags target values that exceed the threshold (default 1.5×) of the source length. The same threshold is used for the max-characters column in CSV export.
  • Exact match warnings flags segments where the target is identical to the source and may not have been translated yet.
  • Special character warnings flags < > " & ` in target values.
  • Placeholder warnings flags missing or extra placeholders in the target. Skipped for ICU strings (ICU validation handles variables instead).
  • ICU format validation flags missing cases and variable mismatches against the source.
  • ICU sub-field editing edits each case in its own field; also lets you add cases the source does not have. Works independently of ICU format validation.
  • ICU CSV export splits ICU strings into one row per case in the exported CSV.
  • Hide non-editable rows hides booleans, numbers, and objects, leaving only translatable strings.
